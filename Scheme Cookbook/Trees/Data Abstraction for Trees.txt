When we constructed the tree (check construction-tree.rkt), we defined some common principles to define a tree.
A tree has at least one node, every node has a datum and and nodes can have any number of children.

The straight-forward implementation is:
(define make-tree cons) > constructor
(define datum car) > selector
(define children cdr) > selector

The selector children is a list of trees, ie children of a node. These children are themselves trees. We call them forest, ie a list that contains multiple trees.
Tree and Forest are 2 different data types. A forest is just a sequence whose elements are trees. We manipulate forests using cons, car, cdr etc but a tree is not a sequence and should only be manipulated by tree constructors and selectors.
